# 流程：office-task（一次性办公文档）

适用：周报 / 实习日志 / 申请材料 / 邮件草稿等"写完就交"的文档任务。
多章节、多轮改稿、多写手的重型文档 → 分流 04-doc-production 骨架。

## 步骤

### 1. 三要素对齐【门禁：与用户确认后再动笔】
- 给谁看（读者与语境）/ 要达到什么效果（目的）/ 有什么素材（已有的与缺的）
- 缺的素材列清单向用户要；数据、经历、事实**一律不虚构**（见 AGENTS.md 诚信纪律）

### 2. 写作（按 report-writer 约束）
- 平实直述，符合提交者身份与语气；格式按对方要求（模板/字数/截止）
- 结论与诉求有素材支撑；数字、日期、名称逐个核对

### 3. 自检（self-checker 三态判定，缩略版）
- 事实核对：每个数字 / 日期 / 名称有出处
- 格式要求逐条过（字数、模板、提交渠道）
- 语气与目的匹配：重读一遍，删空话与套话

### 4. 交付
- 按对方渠道提交；本地按 {{NAMING_RULE}} 存 `deliverables/` 对应子目录并 git commit 留档
