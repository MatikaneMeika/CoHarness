# 流程：bugfix（缺陷修复）

## 步骤总览

```
复现 → 归因 → 建任务卡[门禁] → 最小修复 → 回归 → 记录收尾
```

## 步骤明细

### 1. 复现
- 写出最小复现步骤，能脚本化就写成 `tests/` 里的失败用例
- **复现不了就停**：列为待确认问题向用户要更多信息（环境、输入、日志），禁止"盲修"

### 2. 归因
- 根因用一句话说清（"X 函数在空列表时返回 None，调用方未判空"）
- 列出影响范围：这个根因还会影响哪些调用方
- 区分：代码 bug / 环境问题 / 依赖版本问题 / 使用方式问题——后两类可能根本不用改代码

### 3. 建任务卡 【门禁：用户确认修复方案后动手】
- 卡里必须包含：根因、修复方案、回归测试要求

### 4. 最小修复
- 只改导致 bug 的最小范围
- **禁止顺手重构**相邻代码；看到别的坏味道 → 开新任务卡
- 修复同时补回归测试（复现用例转正为测试）

### 5. 回归
- 原复现用例通过 + `{{TEST_CMD}}` 全量通过

### 6. 记录收尾
- 任务卡 → `done`
- CHANGELOG 记录：日期 + [修复] + 根因一句话 + 影响文件
- 若根因暴露了规则/流程漏洞（如缺输入校验是普遍现象），在任务卡里向用户建议是否改 AGENTS.md
