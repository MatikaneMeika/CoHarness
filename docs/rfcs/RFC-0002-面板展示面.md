# RFC-0002 — 增加展示面：只读看板面板（多级页面 + 验收清单当完成度）

- 状态：采纳（本轮实现）
- 日期：2026-09-28
- 提出人：用户（本仓库维护者），触发点是"多 harness 并行时看不出谁在做什么、做到哪一步"
- 落点：新增 `board.py`（装配与渲染）+ `panel.py`（终端循环）；`pyproject.toml` 加第四个入口
  `coharness-panel`；`README.md` / `README.en.md` / `SECURITY.md` / `tests/` 同步；
  **不改** `wsc.py`、`scripts/check.py`、四套骨架的 `AGENTS.md`

## 问题

三个都是实测到的，不是设想：

1. **协作状态不可见**。03 骨架把状态全写在文件里（卡片 frontmatter 的 `status`/`assignee`、
   `AGENTS.md` 的单写者所有权表、`.agent/telemetry.jsonl`），但要一次看全"哪个 harness 在做哪张卡、
   做到哪一步"得串三条命令：`wsc stats`、`wsc check --stale`、`git log`。
2. **勾选对机器完全不可见，而它是唯一写着的完成度**。卡片约定第 4 节就是
   `## 验收清单` 的 `- [ ]` 项，角色规程也**要求**勾：
   `.agent/roles/coder-frontend.md:32`、`coder-backend.md:32`「任务卡验收清单逐条勾选」、
   `reviewer.md:23`「验收清单勾选完整」。但 `scripts/check.py` 里搜不到 `验收清单` 与 `[x]`——
   勾与不勾不产生任何机器反馈。
3. **同一张卡在不同工作树里分叉，今天无人报警**。`.coh-p2` 演练实测：
   `work/wt-a`、`work/wt-b` 上 `T-101` 是 `status=review`、验收清单 1/1 已勾
   （提交 `6571da6 T-101 收工流转：doing → review，勾验收清单并填交接说明`），
   而 `seed` 与 `work/proj` 上同一张卡仍停在播卡提交 `89f494c` 的 `todo` + 0 勾。
   这种分叉只有把多份副本并排摆出来才看得见。

复现第 3 条：`python panel.py --plain --project ../.coh-p2/work/wt-a`，看卡详情一节
「各工作树副本」会把三份的 status/勾数并排列出并标 `跨工作树分叉`。

## 约束

- **分发面纯标准库、零网络**（`SECURITY.md`）：面板不许变成新的运行期依赖，也不许出网
- **`AGENTS.md` 是唯一权威，不制造第二规则文档**（ADR-5）：面板只**读**权威表，不回写、不另立状态
- **卡片只认声明子集，子集外响亮失败**（`CARD-CONVENTION.md`）：面板不得自己再写一套 YAML 解析
- **他人卡的唯一写者是他自己**（所有权表；I-006 的教训）：面板不得替角色写卡、写交接行、改状态
- **`wsc.py` 行数封顶 1250，新命令不再进分发面**（ADR-10 附注）：面板必须是独立文件

## 备选方案

| 方案 | 做法 | 代价 | 否决理由 |
|---|---|---|---|
| A 什么都不做 | 继续 `wsc stats` + `check --stale` + `git log` 三条串 | 无 | 分叉（问题 3）看不见；角色进度没有呈现面，勾了也没人读 |
| B 把看板做进 `wsc.py` | 加 `wsc panel` | `wsc.py` 已 1205/1250；把 curses/ANSI 循环塞进"curl 单文件"承诺里 | 违反 ADR-10 附注"新命令一律进维护/开发面"；单文件分发物被撑破 |
| C 用 rich/textual 做可选 extra | `pip install coharness[ui]` | 面板变成"装了第三方才有"；textual 的事件循环要引它的 pilot 测试机制 | 破"零依赖"主承诺；展示面反倒成了依赖最多的面 |
| D 让 `check.py` 执法勾选（不勾就拦提交） | 在卡状态转 review/done 时校验清单全勾 | 改的是复制进每个项目的执法脚本 | 规则通道不允许：这是新约束，只有一个数据点，且会把 reviewer 的门禁挪到提交时机 |
| **E（采纳）** | 新文件 `board.py`+`panel.py`，纯标准库自绘 ANSI，只读；完成度读现有 `- [ ]` 约定，git 与 telemetry 当佐证，两边对不上就报警 | 多两个文件、多一套渲染测试 | 见下 |

## 决定

选 **E**。要点与**被牺牲的东西**：

1. **只读**。面板不写任何文件、不执行认领，只把 `wsc claim` / `wsc check` / `maintain audit`
   的命令印在卡详情页让你复制。代价：看到不一致也得人自己去修，面板不能一键流转。
2. **完成度 = 现有验收清单勾选**，不新增字段、不改卡片约定。代价：**没人勾就是 0%**——
   面板不会让进度自己变绿，它只是把"勾了没提交 / 提交了没勾 / done 但清单未满 / 跨工作树分叉"
   四类不一致显示出来。让角色养成边做边勾的习惯属规则改动，按通道登记为
   `.coh-pilot-03` 的 **I-007**，不在本轮顺手改 `check.py`（见方案 D）。
3. **解析复用项目自己的 `scripts/check.py`**（2026-09-29 起装载走 `importlib` 固定路径 +
   装载期间关闭字节码写入——最初用 `exec(compile(...))` 是为了不在**别人的项目目录**里留
   `__pycache__`，但安全门按 CWE-95 把它判成高危拦截提交，两种承诺就此都保住）。
   这一处理念由
   `tests/test_distribution_surface.py::test_panel_loads_check_py_without_dynamic_execution`
   钉死：`board.py` 零 `exec`/`eval`/`compile`，且装载路径必须是 `<项目>/scripts/check.py`。
4. **角色从所有权表推，不猜**。卡的 `allowed_paths` 最长匹配 `AGENTS.md` 单写者所有权表那一格的
   写者；模板行 `code/<组件>/` 按通配前段 `code/` 匹配。匹配不上就显示"边界没落进所有权表"。
   代价：这是**显示层**推断，不等于执法——I-005 那条"所有权表未进执法"的缺口不因面板而关闭。
5. **终端与数据分开**：`board.py` 全是可断言的纯函数（`project_snapshot` 出数据、`render_*`
   出行、`navigate` 是状态机），`panel.py` 只管按键/清屏/刷新。代价：两个文件而不是一个。
6. **中文按显示宽度对齐**（`unicodedata.east_asian_width`），并留 `--plain` 一次性纯文本出口。
   理由：本机默认终端 conhost 跑全屏 TUI 会花屏，`--plain` 既是逃生门也是可贴给人看的输出。

## 后果

- 新增 `tests/test_panel.py`（条数以 `python -m unittest discover -s tests -p test_panel.py` 为准，不在这写死），含四条硬约束：只读（跑完 `git status --porcelain` 不变、
  不留 `__pycache__`）、老实例降级（`check.py` 缺 `minimal_mode` 仍能读；缺 `load_cards`
  响亮失败并给 `maintain.py migrate` 命令）、分叉必须报（真建第二个工作树改卡再判）、
  模板通配行能推出角色。
- 改 `tests/test_distribution_surface.py`：三面变四面（`LINE_BUDGET` 加 `board.py` 540 /
  `panel.py` 220，`FIRST_PARTY` 加 `board`），并新增上面那条 exec 唯一性用例。
- 改 `tests/test_packaging.py::test_console_scripts_cover_the_four_faces`：入口断言从三个面扩到四个。
- 文档同步：`README.md` / `README.en.md` 的入口清单与自测条数、`SECURITY.md` 增一条"展示面只读 +
  唯一执行点"、`docs/ACCEPTANCE-v1.1.md` 的条数、本 RFC。不留两套口径。
- **对已实例化项目零影响**：面板住在库里，不进骨架、不进 `wsc init` 的复制清单，
  因此 `maintain.py migrate` 不需要新步骤，27 个装机文件数不变。
