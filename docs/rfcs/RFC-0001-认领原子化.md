# RFC-0001 — 认领原子化：把抢卡动作绑成一条命令

- 状态：采纳（已实现，骨架库 commit `9aa0ee6`）
- 日期：2026-09-28
- 提出人：CoHarness 维护者；证据来自实例化项目 `.coh-pilot-03` 的登记 `I-002`
  （`.agent/improvements.md`），以及 `.coh-p2` / `.coh-p4` 两轮真 harness 并发演练
- 落点：`wsc.py`（新增 `claim`）、`03-.../scripts/check.py`（跨卡边界交集执法）、
  `03-.../AGENTS.md` 与 `.agent/workflows/parallel-protocol.md` 的认领节

## 问题

多 harness 并行的先到先得全靠"手工四步"：pull → 改卡 → commit → push。演练里它破了两次：

1. **静默覆盖**：B 不 pull 就改同一张 `T-001`，本地钩子看不见 A 的认领，判它合法；
   push 被拒后按协议"先 pull --rebase 再推"，而 rebase 撞车时人习惯加 `-X theirs`——
   A 的先占被吃掉，main 上只剩 B，且全程无人报警。
   复现（当时的形状）：`tests/test_parallel_race.py::test_b`，修好前挂 `expectedFailure`
2. **认领死锁**：认领本身要改卡片，而卡片改动在挂卡执法下需要一张已认领的卡才放行；
   四条路全 rc=1（`I-001`，已由"卡与登记自授权"闭口）

第 2 条已修，第 1 条的根因是**协议把有顺序要求的动作交给会话记忆去执行**：
只要步骤之间可以被跳过，它就一定会在某次会话里被跳过。

## 约束

- 判定冲突不许另写一套口径——什么算"抢了别人的卡"只能由项目自己的 `check.py` 说（ADR-5：AGENTS.md 唯一权威）
- 分发面纯标准库、零网络；`wsc.py` 可 curl 单文件使用（SECURITY.md）
- 认领失败必须回到干净状态：不许留下半截改动、不许留下没推上去的认领
- 不用 `--no-verify`：钩子是执法点，绕过它就等于证明它没用

## 备选方案

| 方案 | 做法 | 代价 | 否决理由 |
|---|---|---|---|
| A 什么都不做 | 协议继续写"pull 时机三处 + 先 pull 再推" | 每次会话都要靠记忆遵守四步 | 演练已经证明会被跳过；文字纪律拦不住顺序错误 |
| B 只禁止 `-X ours/theirs` | 协议加一句"rebase 卡片时不许用策略选项" | 仍然要靠人判断 | 治的是症状：真正的窗口在"同步与写卡之间"，不在 rebase 参数上 |
| C 服务端钩子 / PR 流水 | 在 origin 上跑 `pre-receive` 判看板合法性 | 要求自建 GitLab 或接受 Actions 延迟；与"clone 即用"冲突 | 把执法点搬出项目，下游用户装不动；且 `wsc claim` 落地后窗口已关，不需要它 |
| D（采纳） | 一条命令绑完：fetch → 变基 → **同步后**读卡校验 → 写卡 → `check.py --tasks` → 真钩子 commit → `push origin HEAD:main`；推送被拒则重新同步再判一次，最多三轮，抢输还原并列出可认领的卡 | 认领这一步必须经过 python（重度手工用户仍可走 backlog CLI 的手工路径，协议保留它） | 窗口在命令内部关闭：不同步就没机会写卡，也就没有覆盖入口 |

## 决定

选 D。三条设计要点：

1. **校验发生在同步之后**：早期写法是"读快照 → fetch → 用旧快照改写"，那还是会覆盖先占者——
   现在的顺序是 fetch/rebase 完成后重新读卡片再判（`wsc.py` 注释里钉着这条理由）
2. **判定复用 `check.py --tasks`**：一 harness 一张 doing 卡、跨卡 `allowed_paths` 交集不得并行，
   都在执法侧；`claim` 只负责"写完让你判，判不过就还原"
3. **失败即还原**：脏工作区先拒；写卡后被执法拒回则还原原文；推送被拒则 `reset --hard origin/main`
   后重来，绝不带着半截状态退出

被牺牲的：认领不再是"随手编辑一个 markdown"的纯手工动作（手工路径仍可用，只是不再被推荐）；
以及 `claim` 需要本地有 python——对 03 骨架来说这个前提本来就已成立（钩子要跑 `check.py`）。

## 后果

- `parallel-protocol.md` 的认领节改成"首选一条命令 + 手工路径保留"，`AGENTS.md` 看板行同改
- `tests/test_claim.py`（9 条，含真双进程同时认领同一张卡恰好一个成功）与
  `tests/test_parallel_race.py::test_b`（`expectedFailure` → 硬断言）
- 外部证据：`.coh-p4` 里两个 `qodercli` 会话抢同一张卡——一方成功进 main，
  另一方被拒且未提交未推送，工作区干净（`docs/CHANGELOG.md` 2026-09-28 演练取证行）
- 仍未闭口的：main 上的**合成态**没人复查（`I-004`）——`claim` 只保证单次认领合法，
  多次合法提交合并后仍可能非法；这部分由 `maintain.py audit` 提供可查面，自动化留待服务端/CI 门禁
- 台账：`.coh-pilot-03/.agent/improvements.md` 的 I-002 状态回写为已晋升
