# docs/rfcs — 为什么需要这张表

CoHarness 的规则改动有两种表达：

- **`.agent/improvements.md` 登记行**：来自真实干活时的摩擦，一行一条，走晋升管线（默认路径）
- **RFC**：需要**论证**的设计决定——引入或否决一个组件、改分层、改状态机语义

改进登记回答"这里疼"，RFC 回答"为什么长成这样"。两者的区别不在大小，在于**要不要留下可辩论的依据**：
被否决的方案如果没有 RFC，三个月后会被人重新提一遍。

## 状态

`草案` → `评审中` → `采纳` / `回绝` / `作废`。采纳的 RFC 若落进骨架，CHANGELOG 里引用其编号。

## 怎么写

1. 复制 `TEMPLATE.md` 为 `RFC-NNNN-标题.md`（编号递增，不复用）
2. 至少写清：问题、被否决的替代方案、决定、后果。**没有替代方案的 RFC 不是 RFC，是通知**
3. 有人在 Issue / 项目登记表里撞到同一件事时，把那条证据链回这份 RFC
