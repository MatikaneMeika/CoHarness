\## 二、三个最大杠杆项目的具体集成方案



\### 杠杆 1：`copier` 替换 W9 的自建 migrate（最高 ROI）



`copier` 是专为"可演进的项目模板"设计的工具，原生支持模板与生成项目的版本化同步【turn0search1】【turn0search3】。其核心机制与本项目的需求完全对齐：



\- \*\*`.copier-answers.yml`\*\* 替代自建 `skeleton.lock`：记录模板源（git 仓库 URL）、生成时的 commit hash、以及实例化时填写的占位符值（如 PROJECT\_NAME、STACK）【turn3search5】

\- \*\*Git tag + PEP 440\*\* 替代自建 `schema: 1` 版本声明：模板打 tag，copier 自动比较版本差异【turn3search5】

\- \*\*Smart diff update\*\* 替代自建 `wsc migrate`：`copier update` 读取 git tag 历史，计算生成项目与新版模板的智能 diff，只应用变化的文件，用户本地改动保留【turn0search1】



\*\*集成步骤：\*\*

1\. 骨架库改造为 copier 模板：`{{PROJECT\_NAME}}` 等占位符改成 copier 的 Jinja2 语法

2\. 用户侧：`copier gh:MatikaneMeika/CoHarness` 替代 `git clone + wsc init`

3\. 03 骨架的依赖选择（backlog / spec-kit / worktrunk）改为 copier 的 `choices` 字段



\*\*这一项直接消灭了 W9 的全部自建工作量，且质量比自建更高。\*\*



\### 杠杆 2：`pre-commit` 框架替换 W1 的 hook 安装 + W12 的 pre-push



GitHub 15.6k 星的多语言 hook 管理标准【turn0search7】，原生覆盖 worktree / 子模块 / 非 git 三场景：



\*\*集成方式：\*\*

\- 骨架里写 `.pre-commit-hooks.yaml`，定义 `check-coharness` 这个 hook id

\- 用户侧：`pip install pre-commit \&\& pre-commit install`，替代 `wsc init` 的 hook 安装逻辑

\- W12 的 pre-push 扩展直接在同一框架里加 `pre-push` 阶段的 hook



\### 杠杆 3：`python-frontmatter` + `jsonschema` 替换 W1 的自写解析器



`python-frontmatter`（eyeseast/python-frontmatter）是 PyPI 上的成熟包，MIT 协议，支持 YAML/JSON/TOML 多种 frontmatter 格式，近期仍在活跃维护【turn7search0】。替换 `parse\_frontmatter` / `\_yaml\_scalar` / `\_yaml\_list\_under` 三个自写正则函数：



```python

import frontmatter

post = frontmatter.load(path)

meta = post.metadata  # 已解析的 dict

content = post.content

```



配合 `jsonschema` 做 CARD-CONVENTION 的 schema 校验【turn2search2】——把 CARD-CONVENTION.md 中手写的格式约束转为 JSON Schema，用 `jsonschema.validate(meta, card\_schema)` 替代手写的字段检查逻辑。

\## 四、自建 vs 复用的最终边界



| 能力 | 处置 | 依据 |

|---|---|---|

| 多 harness 并发认领 / 路径所有权 / 接口变更通知 | \*\*自建\*\*（核心差异点） | 目前无现成开源方案覆盖"多 AI 工具在同一 git 仓库并行写作的纪律层"这一空白 |

| evolve 的 LLM 主观评估（有效性/必要性） | \*\*自建\*\* | 判断维度与本项目协议深度耦合，不可外包 |

| 模板版本管理 / smart diff / migrate | \*\*用 copier\*\* | copier 就是为这个场景设计的，且质量更高 |

| frontmatter 解析 / YAML 校验 | \*\*用现成库\*\* | 工程成熟度高，自写是浪费 |

| git hook 管理 / CI 编排 | \*\*用现成框架\*\* | pre-commit + act 是行业标准 |

| 结构化遥测日志 | \*\*用现成库\*\* | structlog 生产验证 13 年 |

| CLI 架构 / 终端输出 | \*\*用现成库\*\* | typer + rich 是 Python CLI 2026 年的事实标准 |



\*\*复用后节省的工程量估计：\*\* 原 Phase 1 + Phase 2 合计约 14 个 W 项，其中 W1 / W3 / W5 / W6 / W8 / W9 / W12 共 7 项因引入现成方案而工作量从"中/高"降至"低/极低"，约节省整体开发时间的 40%。这些节省下来的带宽应该投入到三个真正不可复用的地方：\*\*协议冒烟剧本的编写、evolve 评估 rubric 的打磨、以及多 harness 演练的真实案例积累\*\*——这才是项目的差异化壁垒所在。

\## 3. Phase 1（0–30 天）：可验证性地基



\*\*主题：\*\* 把 README 的承诺逐条变成 CI 里的事实。此阶段不新增任何协作规则。



\### W1 · check.py 现代化

\- `parse\_frontmatter` / `\_yaml\_scalar` 三个自写正则替换为 `python-frontmatter` + `jsonschema`（CARD-CONVENTION 定义为 schema）。

\- hook 安装迁移到 `.pre-commit-hooks.yaml`（pre-commit 框架），解决 worktree（`.git` 为文件）与子模块场景。

\- 内置 fixture 集：嵌套 list、`#` 注释、引号、空 list、多行值——pytest 在 CI 强制运行。

\- \*\*验收：\*\* fixture 全绿；worktree/子模块/非 git 三场景 hook 装机单测通过。



\### W2 · CI 协议冒烟测试

\- 新增 `.github/workflows/protocol-smoke.yml`，单 runner 内 `git worktree add` ×2 模拟双 harness 提交序列：认领 → 写代码挂卡 → 冲突认领 → 合并。

\- 每步断言 `check.py` 退出码；当前已知的乐观锁缺陷以 `xfail` 标注为 known-issue，Phase 2 的 W7 落地后翻转为硬断言。

\- \*\*验收：\*\* CI 长绿；剧本链接置于 03 骨架 README。



\### W3 · 发布工程

\- `pyproject.toml` → `pipx install coharness`；首个 GitHub Release v1.1.0（tag 固定，兑现“按 release tag 取”的自我要求）。

\- 英文 README（初版机翻 + 人工修订头部）；两个 demo 仓库：多 harness 并行 PR replay（由 W2 剧本录制）、一条 evolve 晋升的 before/after。

\- \*\*验收：\*\* pipx 安装成功率 CI 实测；外部可见 release ≥ 1。



\### W4 · minimal 模式 + 自愈 doctor

\- `wsc init multi --minimal`：零外部依赖起步版——把 `sync` 中已有的 `\_card\_summary` 文件回落升格为正式任务层（`TODO.md` checklist 模式），check.py 检查项同步降级。

\- `wsc doctor --fix \[--yes]`：uv / npm / winget 三通道受控安装。

\- \*\*验收：\*\* 从零 clone 到 harness 首次说“开工：" ≤ 5 分钟，由 CI 计时实测。



\### W5 · evolve 命令化（客观维度收编）

\- 新增 `wsc evolve <project>` 子命令，替代“对任意 harness 说 evolve”：

&#x20; - 机器负责客观维度：fingerprint 校验、跨项目摩擦计数（复用 W6 的数据）、与 ROUTER/骨架文件的机械冲突检测；

&#x20; - LLM 只评估有效性/必要性两个主观维度，评估结果以 JSON 落盘留痕。

\- \*\*验收：\*\* 命令输出结构化评估报告；主观评估有 rubric 与留痕。

\## 4. Phase 2（30–60 天）：证据链与闭环



\*\*主题：\*\* 让改进提案有自动采集的证据，让升级与并发不再靠人肉。



\### W6 · 运行时约定追踪（可观测层）

\- pre-commit 扩展：`check.py` 执行后追加写 `.agent/telemetry.jsonl`（本地、结构化）：`{ts, harness\_id, checks\_run, violations, card}`。

\- 新增 `wsc stats`：解析 telemetry + git log，本地输出\*\*规则遵循率、返工信号（同文件反复修改）、stale 分布\*\*三张报告。

\- 关键设计裁决：本地遥测不是网络遥测——保留 SECURITY.md“零网络”承诺，默认开启、`--no-track` 可关。

\- \*\*验收：\*\* `stats` 报告可稳定生成；追踪数据成为登记门槛“同类摩擦 ≥2 次”的机器证据源。



\### W7 · 跨项目聚合 + 认领原子化

\- `wsc init` 时写入 `\~/.coharness/projects.json`（项目指纹注册）；`wsc improve --cross` 扫描本机全部实例化项目，机械统计同类摩擦——满足计数才允许进入“待审”。

\- `wsc claim <card>`：pull --rebase 循环 → `backlog task edit -a` → commit + push 原子化，失败即回滚；`.agent/locks/<card>.json` 写 harness\_id + 时间戳。

\- `check.py` 的 assignee 冲突由 advisory 升级为 exit 1；W2 的 xfail 全部翻转为硬断言。

\- \*\*验收：\*\* 双并发 claim 必有一方失败且干净回滚（CI 实测）；首条 \[晋升 I-xxx] 出现在 CHANGELOG。



\### W8 · evolve patch 化（晋升带证）

\- evolve 产出物从自由文本改为 patch 文件；`evolve --dry-run <patch>` 在临时目录试装并跑通骨架 CI。

\- CHANGELOG 晋升条目强制三证：diff link + 来源项目 link + CI run link，缺一不得入库；“用户批准”从口头变为“用户点 merge"。



\### W9 · schema 版本 + migrate

\- AGENTS.md 头部 `schema: 1`；生成 `skeleton.lock`（parent\_commit / skeleton / adapters）；`wsc migrate` 默认 `--dry-run` 产出补丁、自动建备份分支。

\- \*\*验收：\*\* 一个公开的 v1.0→v1.1 migrate 演示项目。



\---



\## 5. Phase 3（60–90 天+，设准入条件）：规模化



\*\*主题：\*\* 适配、降级、审计与社区。\*\*触发条件：Phase 1/2 全部验收通过。\*\*



\### W10 · adapter 语义桥（编译器层，按 ADR-5 约束）

\- 按各工具原生语法生成指针：CLAUDE.md 用 `@AGENTS.md` import；Cursor 用 `.cursor/rules/coharness.mdc`（alwaysApply frontmatter）；Copilot 用 YAML 头；GEMINI / windsurfrules 按各自格式。

\- 编译产物只含：指针 + 工具特定元数据 + 执行提示，\*\*不含第二份规则\*\*。

\- `wsc adapters --verify` 跑每工具原生 lint。验收：五工具本地 lint 全过。



\### W11 · 依赖降级规格化

\- 每骨架 AGENTS.md 增加“降级行为"节：backlog 缺失 → `TODO.md` checklist 模式（丢失看板/stale 能力，行为显式声明）；worktrunk 缺失 → 普通分支 + 串行协议。

\- `wsc doctor --simulate-missing=backlog` 展示降级后果；建立依赖版本固定 + EOL 预警清单（扩展既有“组件选型记录”）。



\### W12 · audit 子命令 + 可选 pre-push

\- `wsc audit`：检测 `.agent/` 外的 improvements 写入痕迹、AGENTS.md 非 init 流程修改（对比 lock hash）、hook 被篡改。

\- 文档化“CoHarness 安全边界不覆盖的范围"（harness 自身网络行为、IDE 遥测、模型 API 传输）。



\### W13 · 接口契约通知（B 分析采纳）

\- 所有权表扩展“路径 → 对外接口”映射；spec 变更时在相关任务卡生成变更通知标记，要求受影响 harness 下次操作前确认。

\- `wsc sync --dry-run`：展示将拉取的变更及对未提交工作的影响面。



\### W14 · 社区（视 W3 数据）

\- CONTRIBUTING + RFC 流程；中立化 repo 命名评估；≥50 注册指纹后\*\*重启去中心化审核池提案\*\*（ADR-3）。

\## 6. 明确放弃 / 推迟项（决策记录）



| 编号 | 决策 | 理由 | 重启条件 |

|---|---|---|---|

| ADR-1 | 否决 SQLite/数据库状态层 | 违反“文件即真相”第一原则；git + markdown + lock 已覆盖需求 | 无 |

| ADR-2 | 否决 RAG 动态注入 | 骨架上下文规模小，内建“任务→角色”路由即声明式裁剪；RAG 基础设施成本与收益倒挂 | 单骨架注入 token 持续 > 8k |

| ADR-3 | 推迟去中心化审核池 | 无社区基数，先中心化跑通证据化闭环 | ≥50 实例化项目指纹注册 |

| ADR-4 | 推迟 LLM-as-Judge + SWE-bench CI | 成本与稳定性不可控；与多 harness 纪律场景匹配度低；先用协议冒烟 + 本地 stats | 冒烟与 stats 稳定运行 2 个月且社区明确提出 |

| ADR-5 | adapter 采用“格式合法化编译”而非规则双写 | 保持 AGENTS.md 唯一权威不破例 | 无 |

| ADR-6 | 推迟 VS Code 插件 | git hook 层覆盖 80% 场景，成本差一个数量级 | Phase 3 后复评 |

\## 8. 风险与应对



| 风险 | 应对 |

|---|---|

| 单作者带宽不足 | Phase 1 范围已压缩至纯自动化可交付项；所有 W 项优先级内建降级路径 |

| LLM 主观评估不一致 | rubric 化五标准 + 评估 JSON 留痕（W5） |

| 外部依赖 EOL | 降级规格（W11）+ 版本固定清单 |

| migrate 工具自身出 bug | 默认 dry-run + 自动备份分支 |

| 本地遥测被误读为“遥测” | SECURITY.md 显式声明“本地分析、零上传、可关" |



\---



\*\*结语：\*\* 这份计划的本质是把三轮评审收敛为一条主线——CoHarness 从“作者自用工作流笔记”翻到“外部可用基础设施”的分界线，不在规则的完备度，而在\*\*承诺与验证之间的最短路径\*\*。Phase 1 全部完成后，项目就已经跨过这条线；Phase 2 让它开始积累别人复制不了的资产（带证据的约定进化史）；Phase 3 及之后的激进项（ADR-3/4）届时自会有数据来裁决。
