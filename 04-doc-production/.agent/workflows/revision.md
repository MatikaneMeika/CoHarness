# 流程：revision（改稿 / 降重）

适用：收到修改意见、查重后需改写、风格调整。

## 步骤

### 1. 意见登记
- 把所有修改意见列成清单：每条 = 位置 + 意见 + 处理角色（content-writer / reducer / outline-writer）
- 意见之间冲突时先问用户（常见：字数要减 vs 内容要加）

### 2. 回源修改
- **铁律：先改 `source/`，再导出**；禁止直接改 export/ 里的 docx/pdf
- 表述类意见 → reducer（守红线：数字/引用/专名/语义不变）
- 内容类意见 → content-writer（只动对应章节，⚠ 新事实先确认）
- 结构类意见 → 回大纲门禁（改动超过一章，让用户再确认一次）

### 3. 重新导出 + 复核
- 重新导出 `{{DOC_NAME}}.docx/pdf`
- checker 复核：改过的位置已生效、未改的部分未受影响（diff 对照）、清单更新

### 4. 记录
- `docs/CHANGELOG.md` 记一条：改了什么、为什么
- git commit（源 + 产物）

## 反模式（出现即停）

- 在导出物上直接改字
- 为降重把数字/结论也"改写"了
- 第 N 轮意见散落在聊天记录里没进清单，改漏
